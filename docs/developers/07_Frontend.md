# 07 – Frontend Architecture

# Frontend Overview

The frontend is the user interface of MICEPP Scanner.

It provides investigators, analysts and administrators with a secure web application for interacting with the forensic platform.

Unlike the backend, which performs analysis and data processing, the frontend is responsible for presenting information, collecting user input and communicating with the REST API.

The frontend is implemented as a responsive React application.

---

# Objectives

The frontend has several primary objectives:

* Provide an intuitive forensic investigation interface.
* Allow secure authentication.
* Display investigation cases.
* Manage digital evidence.
* Visualize analysis results.
* Support expert review.
* Display audit information.
* Manage AI models.
* Generate reports.

The frontend never performs malware analysis itself.

All security-sensitive operations are delegated to the backend.

---

# General Architecture

```text id="fq2l90"
            User
              │
              ▼
        React Frontend
              │
     HTTP / REST API
              │
              ▼
      FastAPI Backend
              │
              ▼
 Database & Analysis Pipeline
```

The frontend acts as a presentation layer between the user and the backend services.

---

# Authentication

Users must authenticate before accessing the platform.

Authentication is based on JWT tokens issued by the backend.

Typical workflow:

```text id="kp48ms"
Login

↓

Credentials

↓

Backend Authentication

↓

JWT Token

↓

Authenticated Session
```

After successful authentication, protected API requests include the token for authorization.

---

# Main Navigation

The application is organized into several functional sections.

Typical modules include:

* Dashboard
* Cases
* Analyses
* AI Models
* Audit Log

Each section focuses on a specific stage of the forensic workflow.

---

# Dashboard

The dashboard provides a global overview of the forensic laboratory.

Typical information includes:

* Open cases.
* Preserved evidence.
* Pending reviews.
* Recent analyses.
* Detection statistics.
* Analysis engine status.

The dashboard allows investigators to quickly assess the operational state of the platform.

---

# Case Management

Cases represent forensic investigations.

The frontend allows users to:

* Create cases.
* View existing cases.
* Edit case information.
* Track investigation progress.

Each case acts as a container for digital evidence and associated analyses.

---

# Evidence Management

Evidence is uploaded through dedicated forms.

The interface allows users to provide contextual information such as:

* Evidence label.
* Evidence type.
* Acquisition identifier.
* Investigation notes.

The upload process streams the file to the backend, where integrity verification is performed.

---

# Analysis View

The analysis interface displays the results generated by the analysis pipeline.

Typical information includes:

* Analysis status.
* Automated verdict.
* Risk score.
* Pipeline stages.
* Technical findings.
* Human review status.

This view allows investigators to understand how the final assessment was produced.

---

# Human Review Interface

Automated analysis does not conclude an investigation.

The frontend provides dedicated controls allowing reviewers to:

* Validate an analysis.
* Reject an analysis.
* Request additional investigation.
* Classify artifacts.
* Provide review comments.

This supports the Human in the Loop principle adopted throughout the platform.

---

# AI Model Management

The AI module has a dedicated interface.

Typical operations include:

* View available models.
* Review model versions.
* Launch training.
* Activate a model.
* Monitor training status.

Only authorized users may manage machine learning models.

---

# Audit Log

The audit interface displays the forensic audit chain.

Users can inspect events such as:

* Authentication.
* Case creation.
* Evidence upload.
* Analysis execution.
* Report generation.
* Review decisions.

The audit log provides transparency and traceability throughout the investigation lifecycle.

---

# Report Access

Completed forensic reports can be viewed and downloaded from the interface.

Each report summarizes:

* Evidence metadata.
* Integrity information.
* Findings.
* Risk assessment.
* Expert validation.
* Audit verification.

Reports are intended to support forensic documentation and investigation records.

---

# Communication with the Backend

The frontend communicates exclusively with the FastAPI backend.

Typical API operations include:

* Authentication.
* Case management.
* Evidence upload.
* Analysis requests.
* Report retrieval.
* Audit verification.
* AI model management.

Business logic is intentionally kept on the backend.

---

# Responsive Design

The interface is designed to adapt to different screen sizes.

The responsive layout allows investigators to access the platform from:

* Desktop workstations.
* Laptops.
* Large displays.

The primary target remains professional desktop environments used during forensic investigations.

---

# Design Principles

The frontend follows several architectural principles:

* Clear navigation.
* Minimal visual complexity.
* Separation of presentation and business logic.
* Responsive design.
* Secure communication.
* Human-centered workflow.
* Consistent user experience.

These principles improve usability while preserving the integrity of forensic operations.

---

# Future Improvements

Potential frontend enhancements include:

* Advanced search and filtering.
* Interactive investigation timeline.
* IOC visualization.
* MITRE ATT&CK mapping.
* Threat intelligence dashboards.
* Real-time notifications.
* Multi-language support.
* Dark and light themes.
* Customizable analyst workspace.

The modular architecture allows new interfaces to be added without redesigning the existing application.

---

# Summary

The frontend provides the operational interface of MICEPP Scanner.

It enables investigators to manage forensic cases, upload evidence, review analyses, inspect audit records and interact with the platform securely through the REST API.

By separating presentation from backend processing, the frontend remains lightweight while supporting the complete forensic investigation workflow.
